# Jarvis

Standalone desktop assistant in development. Local commands, scoped filename search and opening found files in their default app, permission-gated macOS app launches and Downloads-folder opening, HTTPS website opening, approved Chrome web research and interactive browser tasks, a limited VS Code handoff, and GLM-5 text requests with reviewed Python proposals are available. File-content tools, voice, and general workflows are not implemented.

## Run

Requires Node.js 24+ and npm. From this directory:

```sh
npm install
npm run dev
```

The desktop app opens with Vite at `http://127.0.0.1:5173` (loopback only). Closing the window hides it; use the tray/menu-bar item or `Cmd+Shift+J` on macOS (`Ctrl+Shift+J` on Windows) to reopen. Jarvis also opens its dedicated Chrome session on launch and reopens it with Jarvis if you closed Chrome; hiding Jarvis leaves its tabs open. Use the tray's **Quit Jarvis** item to exit. New chat opens a blank task tab without deleting earlier task tabs; select a waiting task's tab to reply to it. The latest 100 task summaries persist across restarts, while Python proposal tabs and file-search tabs are session-only. Use the tray's **Quit Jarvis** item to exit. Run `npm run build`, `npm test`, and `npm run lint` for checks. `npm start` loads the last production build after `npm run build`. This is an unpackaged development application, not a signed installer.

Try `help`, `show status`, `show time`, or `wait 5 seconds` (cancel the wait in the task list). On macOS, submit `open photos`, `open <installed app name>`, or a direct request such as `can you open the terminal`. Jarvis asks before the first launch, saves a grant for that app alone, and lets you revoke it in Permissions. `open vscode`, `kholo vscode`, and `vs code open krdo be` launch VS Code with the same app-specific grant. Allowing Terminal to launch does not authorize running shell commands. macOS must be able to find the named app. Submit `find report`, `can you find report on my desktop`, or `resume kaha h` to search filenames in Desktop, Documents, then Downloads step by step.

Submit `open my Downloads folder` to open Downloads in Finder; if it has not already been approved for file search, select that exact folder in the native picker first. This grants filename-search access to Downloads until revoked. Submit `open https://example.com` or `open this website https://example.com/report` to open an HTTPS URL in the default browser. Jarvis asks for an origin-specific browser grant, revocable in Permissions. Other URL schemes, credentials in URLs, and requests phrased as questions do not trigger desktop opening. These actions do not read webpage or file contents. If a GLM-5 website-opening action fails because its `browser.open` grant is missing, reply `i allow` immediately in Assistant: Jarvis shows a native confirmation for that exact origin, saves the opening grant if approved, and retries the failed request. A chat reply alone never grants access; a `browser.read` grant shown in Permissions does not authorize `browser.open`. Other failed actions and unrelated replies cannot use this retry.

Submit `search for VS Code on Google` or `search the web for VS Code` to open Google results in your default browser. `open Safari search VS Code` opens those results in Safari after both a Google website grant and a Safari app grant. A plain `search for report.txt` remains a filename search. Opening search results does not read the page or return an answer in Jarvis; inspect the browser yourself. Phone-number lookups such as `search for 6388056383 on google` instead use the approved research flow and check for the exact number on inspected pages. Search terms are sent to Google when the browser loads the URL.

On macOS with Google Chrome installed and your own GLM-5 key configured, submit `research: OLED vs mini LED monitors` to compare web pages, or `research https://bhavishya.site` to inspect that exact website. Natural-language comparisons and train-timing questions trigger source-backed topic research without a separate `browser.open` grant. A factual question containing exactly one HTTPS URL reads that page directly, except train-timing questions, which search for timetable sources. If the direct page cannot be read, Jarvis does not substitute search results. Multi-site comparisons remain topic searches, where supplied URLs are search hints, not proof that the pages were read. Requests such as `delhi weather` and `delhi police phone number` also trigger research; `delhi todays time` uses the local clock in the Asia/Kolkata time zone. For an explicit research URL, Jarvis reads the requested HTTPS page directly and does not substitute similarly named search results; if it cannot read the page, it returns an error instead of answering from other sites. For a topic, Jarvis opens a temporary Chrome session by default and collects results from Google, DuckDuckGo, and Brave when readable; it interleaves their links, visits up to four readable pages, and attempts a follow-up search within one source site. DuckDuckGo may present a challenge instead of results. Public Instagram pages can be discovered through these engines, but login-gated pages cannot be read in the default temporary mode.

Public HTTPS reads are automatic in temporary research; revoked sites remain blocked until explicitly re-allowed in Permissions. Skipped sites are not read. Only inspected page text (about 4,500 characters per page) and source URLs are sent to GLM-5. Phone-number lookups search the exact digits, use only pages showing that complete number, and can report a public business listing if the source supports it; they do not establish the owner of a private number. Google AI Mode is not integrated or read by Jarvis; GLM-5 drafts the source-grounded answer. Source pages run without scripts; non-document requests, downloads, non-HTTPS pages, and local/private network addresses are blocked. Search and page visits are visible to those websites. Google may block automated sessions with an unusual-traffic verification page; results depend on website availability and approval. Sites requiring JavaScript may be unreadable in either mode; fewer than two readable pages for other topic searches produces an error rather than a comparison. Results are limited to four sources, so they are not exhaustive, and source claims still need verification. Cancellation closes the research Chrome session. Ordinary Google/Safari search continues to open results without reading them.

After a direct-site research question, an immediate informational follow-up can revisit that same HTTPS page, including after a restart. It checks read permission again and does not restore the earlier browser session. A short action follow-up can reuse the site from the immediately preceding browser-use request, with browser-use permission and action review checked again; task history never grants website access. After a browser-use cab/ride request with a pickup, destination, and Uber or Rapido, an immediate reply such as `Search it in Uber also` or `Try Rapido again` reuses the original route for a new single-site search, even if the previous search failed or Jarvis restarted. The Assistant shows the active ride route and a Search Uber action. A new conversation or unrelated task ends this follow-up context. Results and fares must be observed on the new site; partial progress on another site is not a confirmed ride or booking.

`open vscode` also lists active VS Code window names. Projects found under already approved read folders can be selected directly; for other projects, choose the exact folder in the native picker. Jarvis opens the chosen folder in VS Code, then offers a separate chat prompt with a confirmation before handing it to VS Code's agent chat via its CLI. Keep the chosen project as the last active VS Code window: the CLI's `--reuse-window` flag targets that window, not a folder path, so Jarvis cannot guarantee the prompt goes to the chosen project. Selecting a folder does not grant Jarvis permission to read its files. A successful CLI handoff does not mean the agent completed the request: Jarvis cannot observe VS Code chat progress or verify its result. Review the target window, progress, and any proposed edits in VS Code. This handoff depends on the installed VS Code `code` CLI and an available chat provider in VS Code.

`open vs code smartyai project` routes to project selection, never to an app named "vs code smartyai project". If the project is not uniquely found among approved active projects, choose the folder named `smartyai` in the native picker. Opening a project falls back to macOS `open` if the `code` CLI is not installed; listing open projects then shows no detected windows, and sending a chat prompt still requires the `code` CLI.

Screenshot requests such as `todays screenshot`, `yesterday's screenshots`, `show screenshots from 2026-10-12 between 09:00 and 11:00`, and `last screenshot` search approved folders for images from the requested local calendar day and optional 24-hour local time window. A follow-up such as `between 09:00 and 11:00` reuses the preceding result's date. The screenshot filename capture timestamp takes precedence over modification time, which is used when the filename has no date. With GLM-5 configured, Jarvis can extract a date from less explicit screenshot requests; otherwise specify today, yesterday, last, or an ISO date. GLM-5 only extracts the date and never reads the images. The last-screenshot request shows every matching image from the newest screenshot's date. Results are ordered newest-first with in-app thumbnails generated for approved images up to 25 MiB, plus a Show in Finder button. The Photos app library is not connected: to search its images, export them to Desktop, Documents, or Downloads first, then search the exported screenshot files.

For each ungranted folder, Jarvis shows a permission dialog: allow that named folder to start searching it immediately, or skip it. It continues through the remaining approved folders even after a match, ranking exact filenames in shallow folders first for ordinary searches so a Downloads copy is not missed behind a deep project asset. A search result has separate Open with default app and Show in Finder buttons; both work only while the file exists, remains in the latest search results, and its folder grant remains active. Opening a spreadsheet starts its associated application; Jarvis does not read or edit its cells. The Permissions page accepts absolute folder paths, then requires selecting the same folder in the picker. On macOS, search checks Spotlight's index within each approved folder first, verifying each result is an existing file inside that folder. If the index has no usable match or is unavailable, a filesystem fallback checks up to 5,000 entries for ordinary searches or 100,000 for screenshot searches, and four nested levels per folder; incomplete searches are reported. Ordinary results are limited to 20 matches; screenshot results to the newest 200, with a warning if truncated. Search does not read ordinary file contents; screenshot previews read only validated approved image results. macOS can still deny access independently; a Jarvis grant cannot override System Settings > Privacy & Security > Files and Folders or grant Full Disk Access.

For an action request such as `python: print 2 + 3` or `create a file using Python`, GLM-5 proposes Python code in the assistant view. Nothing runs until you review the full code and choose **Approve and run once**. Denial or expiry prevents execution; the approval is not a persistent grant. Proposals target the Python 3.9 standard library: Jarvis runs `/usr/bin/python3 -I`, so installed third-party packages such as `requests` may be unavailable; HTTP code should use `urllib.request`. Python runs with your user account and is **not sandboxed**: approved code can access files and the network, so only approve code you understand. Execution is limited to 10 seconds and 32 KiB of output. This is a preview-and-approve workflow, not an autonomous agent or a general-purpose safe automation sandbox. The microphone button is disabled. The latest 100 task summaries persist across restarts; Python results appear in the assistant view, not task history.

By default, research uses a fresh temporary Chrome profile for each task. Source pages are read in a separate script-disabled context with per-origin approval. If one search engine blocks the session, Jarvis still tries the other approved engines. This does not integrate Google AI Mode or guarantee an answer for unlisted/private phone numbers.

## Interactive browser tasks

The plain request `brows bookmyshow search ticket for mirzapur near my location for 16oct` routes to BookMyShow browser-use, not GLM's generic website-opening tool. Jarvis asks for your city and area or PIN code, whether Mirzapur means a show or a city, and missing seat details before browsing. It does not determine your location from the device or confirm ticket availability without inspecting the site.

For `Find restraunt near my location in 200 meters` or `browse-use: restraunt near my location in 200 meters`, Jarvis asks for an exact address or map pin and city in Assistant before starting browser-use unless you previously saved a comma-separated address with a six-digit PIN. It does not search local filenames or read device location. Sharing a saved address with GLM-5 still requires one-time consent for that task. The requested radius is used when supplied (200 meters by default). Results must have inspected distance evidence; when a distance cannot be verified, Jarvis says so rather than claiming a restaurant falls within the radius. Live nearby results are not guaranteed.

`browse-use: get the ticket from the book my show app 2 seat near new ashok nagar delhi` starts browser-use on the public BookMyShow website, not read-only research or the installed app. It can navigate and look for shows in the requested area without an initial public-site read prompt. If no movie or showtime is specified, it should report observed options and ask you to choose, not claim seats are booked. Consequential booking actions still need one-time approval; no reservation is confirmed without a verified result. `find the nearest dominos and order 2 large pizza in my location` starts on Domino's official ordering origin, `pizzaonline.dominos.co.in`. Supply an exact delivery area or address and the pizza variants; Jarvis must review the cart, delivery address, and full total before submission. Complete QR payment yourself if offered, and rely on the site's confirmation before treating the order as placed. This workflow has not been verified end to end. `browse-use: search the latest price of iphone croma store` starts on Croma; requests without an explicit or recognized site first check whether exactly one active public read grant in Permissions matches a site name in the request, then use research to discover readable sources if none matches. An unrelated, revoked, open-only, or signed-in-only grant is not selected.

For a price comparison, ask `compare cheap pizza delivery and order 2 large pizzas near me` (include dietary or topping preferences if needed). Jarvis asks for your delivery area, city and six-digit PIN code in the Assistant chat unless you saved an area with a PIN; then it continues the same task after your reply or uses the saved area. A chat reply stays in the current session and is not saved as a contact. It checks Domino's and Pizza Hut in separate single-origin browser sessions. It compares only reported delivered totals for two large pizzas, including fees; if either price is unavailable, it does not start checkout. If both prices are returned, it starts a guarded order on the lower-priced site. Each address-bearing step asks before sharing the delivery request with GLM-5. Checkout form details for this comparison are also requested in chat without saving contacts. Verify the cart and current total before approving an order action. After a successful browser run, the order Chrome window stays open for you to inspect and pay yourself; reply `done` in Assistant to end the handoff or `stop` to close the task. Neither reply verifies payment or order confirmation. A cancellation or unrecoverable browser failure may close Chrome earlier. Live prices and an end-to-end checkout have not been verified.

The complete upstream browser-use Python project is copied into `browser-use/` (upstream MIT license retained). Its local `.venv` is excluded from version control. To reproduce the environment after cloning Jarvis, run `python3.12 -m venv browser-use/.venv` then `browser-use/.venv/bin/python -m pip install -e ./browser-use`.

For `browse-use: get my exact location`, Jarvis opens `https://mylocationapp.com/my-location/` directly instead of using search results. It asks separately before allowing that site to request device location in a temporary Chrome session; declining stops the lookup. The site and GLM-5 may receive the location, and macOS or Chrome may still be unable to provide it. An IP-based city estimate is not accepted as a precise location. Jarvis offers a saved-area suggestion only when the reported address is visible on the approved site's current page; review it before saving. The Chrome session closes after this lookup.

For `browse-use: book a train ...` or `book a train ...` (including the typo `trian`), Jarvis gathers the direction and stations, date with year, passenger count, class and quota before opening IRCTC. With GLM-5 configured, it asks one contextual question at a time, understands short replies in the context of the last question, and requires your confirmation of the full search summary; reply `stop` to cancel or correct a detail before confirming. Without a configured key, it uses a single fixed details prompt. It does not assume a train name you did not specify. Other browser workflows still use their own clarification prompts or the browser agent's follow-ups; this is not a general conversation planner. Verify the train number and live availability in Chrome. A timetable or seat-availability summary is not a booked ticket, and payment and final booking remain subject to your review and the site's confirmation. The clarification and cancellation were tested in the desktop app, but no live booking was verified.

Submit `browse-use: inspect https://example.com`, `browser-use: get the email from example.com official mail`, or `browse-use: search the latest price of iphone croma store` to use the cloned browser-use Agent. A bare domain is treated as HTTPS; requests naming multiple websites are rejected. If no website is identified or uniquely matched to an active read grant, temporary research Chrome searches and inspects public results before browser-use visits up to two distinct readable source sites in separate, sequential origin-scoped sessions. Search requires at least two readable sources; blocked search engines or inaccessible pages may prevent discovery. If these discovered browser-use visits stop or time out without a verified result, Jarvis can answer only from the already inspected research extracts, citing them and without claiming that any browser action succeeded. Denial or cancellation does not trigger that fallback. The agent uses GLM-5, a local Chrome session scoped to one public HTTPS origin, and at most 40 model steps per site. After a successful task or a recoverable 40-step exhaustion, its visible browser remains open; inspect the page yourself and submit another `browse-use:` task on the same origin to reuse it. A task on another origin closes the old browser and opens a new one. Cancellation, denial, worker errors, revoking a site's read permission, and quitting Jarvis close the browser; sessions do not survive an app restart and are separate from the `browse:` Chrome session. This lifecycle has been tested with a local worker, not a live GLM-5 browsing run. Approving a SharePoint origin does not sign this temporary Chrome profile into Microsoft or grant access to a private workbook. Manual sign-in may require cross-origin redirects blocked in browser-use; for a signed-in tab, use the separate `open chrome session` and `browse:` flow with its own read approval. Only report spreadsheet counts after the actual rows have been read and verified. Public site reads receive a revocable grant automatically unless the site was previously blocked. An existing read grant is reused without another site-read prompt. Same-origin reads, scrolling, routine same-site links and tabs, IRCTC station/class/quota selections, and non-sensitive search typing need no per-action approval. Consequential or uncertain clicks (including train-search form submission), password entry, keypresses, and unrecognized actions need one-time review. Cross-origin navigation within a worker run is still blocked by the browser profile even after review. Action status means proposed, not executed; denying or cancelling stops the task without a result. When the agent asks a follow-up question, Jarvis pauses and shows it in Assistant chat; reply there to continue in the same Chrome session, or `stop` to cancel. If the worker identifies a CAPTCHA control, Jarvis asks you in Assistant to solve it manually in Chrome. Reply `done` only after solving it; Jarvis discards the pending CAPTCHA click and resumes observing the page in the same task. The browser task does not time out while awaiting your reply, but closing Jarvis or cancelling ends it. A `done` reply does not establish that the challenge was passed; detection of every CAPTCHA design is not guaranteed. Follow-up detection is limited to explicit questions and requests for missing choices; an agent that finishes without asking still ends its run. Pages can make their own network requests, so the allowed-domain setting is not a full network sandbox. A model-reported result is not independent proof that a site action succeeded. Run `npm run test:browser-use` to test the worker protocol without a live site.

In Permissions, you can save a name, email, phone, or address for a single public HTTPS site. Jarvis asks before saving and offers deletion. By default, values are stored locally in a mode-0600 file under the Electron user-data directory. Set `JARVIS_MONGODB_URI` to use the `jarvis.form_details` MongoDB collection instead; use a restricted account and TLS. Existing data is not migrated when switching stores. Before a browser-use task, Jarvis asks whether to share matching saved values with GLM-5 for that task only. If a contact field is reached without an approved value, Jarvis opens the saved-details form and pauses until you explicitly save and use that field or stop the request. Contact fields entered on the page may become visible to GLM-5. Never store passwords or payment information here.

You can also save an optional full address (up to 300 characters), area and PIN in Permissions. This `location.json` preference stays only in the Electron user-data directory (even if MongoDB is configured), is confirmed before saving, persists across restarts and can be deleted from Permissions. A completed `browse-use:` location lookup can offer a labeled website-suggested address in Assistant; review the answer and choose **Save area on this device** to request native confirmation. Unlabeled or failed results are not offered or saved, and a website's reported address is not verified device location. Earlier browser answers without a labeled suggestion can be pasted into Permissions manually. Nearby ticket requests show the saved area before asking for missing show/date/seat details; pizza comparisons and Domino's orders reuse a saved area with a six-digit PIN without asking you to type the area again. Nearby restaurant searches reuse a saved comma-separated address with a PIN. Incomplete saved details still prompt, and delivery checkout still requires verifying the full address. Site-specific sharing and booking approvals remain in place. The location is sent to GLM-5 when used for those tasks, not to every site automatically. Jarvis does not track device coordinates or save all conversations; the latest 100 task summaries are stored locally, and interrupted browser sessions are not resumed after restart.

On macOS with Chrome installed and GLM-5 configured, submit `browse: inspect https://example.com` or `browse: open https://example.com and click the About link`. GLM-5 can navigate, observe page text and labeled controls, click (left, double, or right), fill text, press keys, scroll, and go back or forward. Without `open chrome session`, `browse:` uses a visible, temporary Chrome session that closes after each task. The model receives bounded page text and controls after each action. Public HTTPS reads in temporary sessions receive an automatic revocable `browser.read` grant; revoked sites require contextual approval. Scrolling, history, observed same-site navigation links, and clearly presentational buttons need no click dialog. Other clicks, fills, keypresses, and double/right clicks still require a separate revocable `browser.interact` grant and one-time confirmation. Review Chrome before approval: controls may have effects on the site. Cancel a temporary task to close its Chrome window.

Jarvis opens a dedicated Chrome profile on launch and reopens it with the tray or `Cmd+Shift+J`; `open chrome session` also opens it explicitly. Sign in and open tabs yourself in that window, then submit `browse: inspect current tab`, `look at my current tab`, or `inspect https://www.irctc.co.in/nget/train-search`. Natural site-inspection requests use this persistent session. Without a URL Jarvis selects the most recently opened HTTPS tab, which might not be the focused tab. With a URL it selects the most recently opened tab on that origin, or starts a blank tab for navigation if none match; the URL does not force navigation to a particular path in an existing tab. It cannot attach to tabs in your ordinary Chrome profile or to tabs opened in earlier temporary browser-use/research sessions. Existing tabs stay open after a `browse:` task finishes or fails; closing Jarvis completely closes this session. The dedicated profile remains on disk for future runs. Before reading an origin in this potentially signed-in session, Jarvis asks for a separate revocable `browser.readSignedIn` grant; page text and controls are then sent to GLM-5. Routine IRCTC station text and station/class/quota choices skip the action dialog; other interactions still require the separate reviewed `browser.interact` approval. Login is manual and Google or other sites may block automated Chrome sessions. The temporary `browser-use:` worker, ticket/pizza workflows, and read-only `research:` flow remain separate and do not reuse these tabs. When the agent is active it blocks non-GET network requests and non-public origins; script-heavy or signed-in workflows may fail. Do not approve reading private tabs whose contents you do not want sent to GLM-5.

Browsing does not type passwords. Temporary browsing uses a fresh profile even when signed-in research is enabled; persistent browsing uses only its own separate profile. Downloads, non-GET network requests during agent tasks, local/private URLs, and unapproved origins are blocked. Dynamic sites needing those requests may not work. Page text is untrusted and is sent to the configured GLM-5 provider; do not approve sensitive pages. This is a limited local browser agent using Playwright and GLM-5, not the complete browser-use Python product, cloud service, CAPTCHA solver, or a guarantee of any website workflow. MongoDB is optional for saved contact details, not browser execution. Live GLM model access and end-to-end website actions have not been verified with a personal key.

## Signed-in Chrome profile

On macOS, submit `setup chrome login` (or `chrome login setup` / `chrome me sign in karo`). Jarvis opens Google Chrome normally at `https://accounts.google.com` using its dedicated profile under Jarvis's application data (`chrome-profile`), never your default Chrome profile. To sign in to a different website such as Naukri, navigate to its URL in that Chrome window and sign in yourself; JavaScript works during manual setup. **Close the Chrome window when finished.** The task remains running until Chrome exits. Jarvis never types credentials or attaches automation during setup. Close any other Chrome window using this profile first; a locked profile is refused. Google may still ask for extra verification or refuse sign-in; this feature does not bypass Google checks.

In Permissions, turn on **Use signed-in profile** and confirm the native warning. This opt-in persists across restarts and defaults to off. When enabled, research opens its controlled Chrome session with the dedicated profile. Every new HTTPS origin requires a separate `browser.readSignedIn` approval, including search providers; ordinary `browser.read` approvals do not carry over. Revoke individual signed-in grants in Permissions. Sites you approve can see your logged-in identity, and extracted page text may include account-specific information sent to GLM-5 for the answer. Do not approve private pages whose text you do not want sent to your configured provider. Jarvis does not extract cookies, passwords, tokens or localStorage; source pages still run without scripts, and only bounded page text and source URLs are included as evidence. Search-provider pages may be unreadable with scripts disabled in this mode. Switching the toggle off restores the fresh temporary profile; the signed-in profile remains on disk until reset.

Submit `reset chrome login` to confirm deletion of the Jarvis-only Chrome profile and turn signed-in research off. Reset refuses while that Chrome profile is in use. Saved per-origin grants can be revoked separately in Permissions. Signed-in Chrome setup and research are not supported yet on Windows or Linux.

## GLM-5 setup

The key is **not** included in the app. Open the project-root `.env` file and put your own Bedrock Mantle key after the equals sign:

```dotenv
BEDROCK_MANTLE_API_KEY=your-own-key
```

Restart Jarvis after editing `.env`. Electron main loads this file on startup; it is ignored by Git and is never included in the renderer. An already set shell environment variable takes precedence. No `JARVIS_GLM_PROVIDER` setting is needed for Bedrock Mantle.

Jarvis uses the same direct provider path as invisible-overlay: `https://bedrock-mantle.ap-south-1.api.aws/v1/chat/completions` with model `zai.glm-5`. Your key must be an **Amazon Bedrock API key** authorized for this model and region. A key issued by the overlay's local backend is not interchangeable with a Bedrock API key. Direct app-launch and filename-search requests are recognized locally. For other task requests, GLM-5 may propose structured calls to open an app, Downloads, or an HTTPS website. Each call requires an existing scoped grant **and** a fresh Open once confirmation; malformed arguments and more than three actions are rejected. Neither model prose nor a saved grant alone triggers an action. Python proposals and screenshot-date extraction remain text-only. File and spreadsheet content access is not implemented.

For a personal [Z.AI API key](https://z.ai/manage-apikey/apikey-list) instead, explicitly set `JARVIS_GLM_PROVIDER=zai` and `JARVIS_GLM_API_KEY` in `.env`. Do not paste any key into Jarvis chat, commit it, or put it into frontend environment variables. This setup is not persistent keychain storage.

Ask a text question to make a real request to the selected provider. **Show status** reports whether a key is configured, not whether it is valid. A successful response confirms this session can use it; 401/403 indicates rejected key or account access, and 429 indicates rate limit or quota. Check billing and model access with the selected provider. Task chat sends your submitted question and the three action tool definitions; when approved, action results are returned to the provider. It does not send folders or task history. No free-tier or unlimited-usage claim is made.

## Architecture and security

- `electron/main.mts`: lifecycle, native tray/shortcut, narrow IPC handlers, renderer navigation blocking.
- `electron/preload.cts`: isolated bridge. Renderer has no direct Node.js or shell access.
- `electron/tasks.mts`: bounded task queue, persisted task summaries, result states and cancellation.
- `electron/glm.mts`: main-process authenticated GLM-5 requests with bounded timeout and validated, bounded client-side tool calls.
- `electron/permissions.mts`: persisted scoped grants, separate anonymous/signed-in HTTPS-origin read permissions, signed-in setting, and revocation.
- `electron/chrome-profile.mts`: dedicated macOS Chrome profile, manual sign-in process, lock checks, and confirmed reset support.
- `electron/browser-research.mts`: temporary-by-default or opt-in persistent Chrome session, per-origin approval, script-disabled source pages, and bounded evidence collection.
- `electron/browser-agent.mts`: temporary interactive Chrome session with public-HTTPS request filtering, per-origin read grants, interaction grants and one-time action confirmations.
- `electron/file-search.mts`: sequential, scoped filename search with explicit per-folder decisions, validated Spotlight results, bounded fallback and macOS access error reporting.
- `electron/python-actions.mts`: ephemeral GLM-5 Python proposals and one-time approvals; no unattended execution.
- `src/bridge.ts`: typed renderer contract; `src/App.tsx`: command view and task history.
- Renderer sandbox and context isolation are enabled, Node integration disabled, and a CSP limits loaded resources. Dev CSP permits Vite's local websocket. No unauthenticated server, startup service, bundled credentials, or file-content tools are enabled. Configured GLM-5 requests go from Electron main to the selected provider.
